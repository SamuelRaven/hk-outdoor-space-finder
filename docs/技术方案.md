# 技术方案

---

## 技术选型

| 项目 | 选择 | 说明 |
|------|------|------|
| 形态 | 纯网页应用 | 手机浏览器打开，无需微信环境 |
| 框架 | 无 | Vanilla HTML/CSS/JS，零依赖 |
| 路由 | Hash 路由 | `#/` `#/filter` `#/results` `#/blindbox` |
| 模块 | ES Modules | `<script type="module">` |
| 字体 | Google Fonts | Josefin Sans + Inter |
| 部署 | 静态服务器 | 任何静态文件服务均可（GitHub Pages 等） |

---

## 文件结构

```
the-little-things/
  index.html                # 单HTML入口
  css/
    reset.css               # CSS reset
    bauhaus-tokens.css      # 设计令牌
    layout.css              # 页面布局
    components.css          # 组件样式
  js/
    data/
      parks.json            # 公园数据集
      districts.json        # 地区映射
    core/
      router.js             # Hash SPA 路由
      matcher.js            # 匹配算法
    ui/
      landing-page.js       # 首页
      filter-page.js        # 筛选页
      results-page.js       # 结果页
      blindbox-page.js      # 盲盒页
      toast.js              # 提示组件
      dice-animation.js     # 骰子动画
    app.js                  # 应用入口
```

---

## 路由设计

| Hash | 页面 | 说明 |
|------|------|------|
| `#/` | 首页 | 默认页 |
| `#/filter` | 筛选页 | 四个筛选器 + GO + 盲盒 |
| `#/results` | 结果页 | 10个公园卡片 |
| `#/blindbox` | 盲盒页 | 1个随机公园 |

## 匹配算法

```
硬性过滤（必须满足）：
  1. 大区匹配
  2. 小区匹配（如选择）
  3. 设施类型兼容（both 类型两边都通过）

加分项（影响排序）：
  4. 项目类别匹配 → +2分
  5. 时段匹配 → +1分

排序：总分降序 → 同分组随机打乱 → 取前10
```
